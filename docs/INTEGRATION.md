# 工具整合計畫：midas-curve-gen → Midas Civil → RC 構件設計工具 → StructAudit-AI

> 本檔為四個倉庫串接的總計畫與交換格式規格（以本檔為準；其他倉庫的 README／CLAUDE.md 只放連結）。
> 需求確認日期：2026-11-07（使用者 JIN）。

## 1. 目標

讓一座 RC 橋梁（墩柱、橋塔、帽梁、橫梁、基樁、版）從「線形建模」到「設計審查」的資料不必手抄：

1. **幾何只輸入一次**：midas-curve-gen 產生的節點／元素／結構群組，就是後續內力歸屬構件的依據。
2. **內力不手抄**：Midas Civil 2022 的結果表格直接貼進 RC 構件設計工具，自動依群組歸到構件、以極值篩選或全部組合帶入、換算成 tf、tf·m。
3. **斷面與配筋雙向**：Midas 斷面尺寸帶入設計工具；設計完成的配筋輸出成 MCT，回寫 Midas 供塑鉸／非線性分析。
4. **可追溯**：每一列設計內力都能追到「哪個群組、哪個元素、哪一端、哪個組合」，並印在計算書，供 StructAudit-AI 審查與技師核對。
5. **審查回饋閉環**：StructAudit-AI 輸出的調整後案件檔，直接在設計工具開啟重算（已可用，維持）。

不在範圍：各工具與串接無關的既有功能（不改動）；四個工具合併成單一程式（不做，維持各自獨立）。

## 2. 工作流程

```
 ① midas-curve-gen（網頁）
    線形 → 節點／元素／結構群組（每個要設計的構件一個群組，例如 P1_COL、P1_CAP、P1_PILE1）
    輸出：model.mct（*UNIT、*NODE、*ELEMENT、*GROUP）
        │
        ▼
 ② Midas Civil 2022
    匯入 model.mct → 指定斷面、材料、邊界、載重、載重組合 → 分析
    輸出 A：Tools > MCT Command Shell 或 File > Export > MCT 的完整模型 .mct（含 *SECTION、*MATERIAL、*GROUP）
    輸出 B：Results > Result Tables > Beam > Force（全選複製，或存成 Excel／CSV）
            版：Plate > Force（M2 起）
        │
        ▼
 ③ RC 構件設計工具（rc-member-designer，網頁）
    「從 Midas 匯入」：讀 .mct（群組、節點高程、斷面、材料、單位）＋內力表
      → 依群組歸屬構件 → 單位換算為 tf、tf·m → 極值篩選或全部組合（柱：同一列為同時內力；梁／版：群組設計包絡）
      → 套用到目前構件，或一次在構件清單建立多個構件
    設計配筋 → 計算書 PDF（含「內力來源」）／Excel／案件檔 .json
    輸出 C（M3）：配筋 MCT（Midas Design > Rebar Input），回到 ②
        │
        ▼
 ④ StructAudit-AI（Streamlit）
    計算書 PDF ＋ 案件檔 → 多輪詰問審查 → 審查報告 ＋ 調整後案件檔
        │
        └──► 回到 ③ 開啟調整後案件檔重算（既有功能）

 ⑤ 書稿《Midas Civil 橋梁結構分析與設計實務》第六篇新增一章，以同一例題走完 ①～④（M6）
```

### 3.1 正負號與軸向對應（X3 → 設計工具）

| Midas（元素局部座標） | 柱模組 | 梁模組 |
|---|---|---|
| Axial（拉為正） | $P_u = -N$（壓為正） | 不用 |
| Moment-y（繞局部 y，深度沿 H） | $M_{ux}$ | 正值＝下緣受拉（$M_u^+$），負值取絕對值為 $M_u^-$（可切換） |
| Moment-z | $M_{uy}$ | 只做側向彎矩警示 |
| Shear-z | $V_{uy}$（與 $M_{ux}$ 同平面） | $V_u$（取絕對值） |
| Shear-y | $V_{ux}$ | 不用 |
| Torsion | $T_u$ | $T_u$（取絕對值） |

斷面：Midas SB 的 B（局部 y 向）、H（局部 z 向）對應設計工具的 B、H；若 Beta Angle 使兩者對調，用「x／y 對調」選項。

### 3.2 匯入方式：極值篩選與全部組合（2026-11-07 改名，避免把篩選結果誤當成控制驗算）

兩件事要分開：**「分量極值」不等於「利用率最大」**。匯入只決定把哪些列交給設計工具；哪一列控制，由設計工具逐列驗算後才知道。

- **極值篩選（快速）**：只列 P、M、V、T 各分量最大／最小所在的組合。設計工具逐列驗算這些列，但未列入的組合仍可能控制（例如軸力與彎矩都不是極值、組合起來卻最不利）。計算書會寫明「極值篩選」。
- **全部組合（逐組驗算，正式設計建議）**：每個勾選的組合都列出，由設計工具逐列驗算找出控制列。
- **柱／墩柱／橋塔／基樁**：每一列是同一組合、同一端點的**同時內力**。篩選依據：在群組內所有元素端點（I、J，及 1/4 等內部點）× 勾選的載重中，分別找 $P_u$ 最大與最小、$M_{ux}$、$M_{uy}$ 正負向最大（該方向確實出現才列）、$|V_{ux}|$、$|V_{uy}|$、$|T_u|$、合彎矩最大的列。
  每個組合輸出構件**頂、底兩端**各一列（同名，供長細效應 $M_1/M_2$ 配對）；篩選點若在構件中間，另加一列「組合 @元素-位置」。頂底以 .mct 節點 Z 座標判定（基樁頂＝樁帽底）。
- **帽梁／橫梁／版**：每一列是該組合在群組內各分量的最大值，稱為**群組設計包絡**——$M^+$、$M^-$、$V$、$T$ 可能來自不同位置，**不是同時內力**。撓曲各自檢核偏保守；剪力與扭矩的交互作用宜逐點檢核（計算書與預覽都會說明）。
- **包絡組合**（名稱含 `(max)`／`(min)`／`(all)`）各分量不是同時發生，會警示並預設不勾選。
- 內力是節點（中心線）值，柱面或支承面折減須自行處理（警示）。
- 橋梁容量設計用的靜載重軸力 $P_D$：可指定一個載重（例如 `DL`）取構件底端軸力填入（預覽列出底端節點）。

### 3.3 載重指紋 v2（判斷匯入後載重表是否被修改）

- 格式 `k2:` ＋每列 `名稱|位置|Pu|Mux|Muy|Vux|Vuy|Tu|Mpos|Mneg|Vu`，列與列以 `;` 分隔；缺欄為空字串。
- 數值：×1000 後四捨五入，**半數一律往 +∞**（$-1062.5 \to -1062$），非有限值記 `NaN`，$|\times1000| \ge 9\times10^{15}$ 記 `OV`。
- 實作：設計工具 `core/midas-io.js` `loadsKey`、StructAudit-AI `utils/rcmd.py` `loads_key`；兩邊都以 `tests/fixtures/loads_key_vectors.json`（StructAudit 為 `tests/data/` 的同一檔）驗證，**改規則時兩邊與向量檔一起改**。
- v1（`toFixed(3)`）在 1.0625 這類捨入邊界與 Python 不同，會誤報「已修改」；只保留給舊案件比對（`loadsEdited`／`loads_edited` 依前綴判斷版本）。

### 3.4 審查寫回（案件檔 `review` 區塊）

- StructAudit-AI 只改 `values`，**不改 `loads`、`bloads`、`loadsrc`**；建議值必須屬於案件所屬模組（柱案件不接受梁欄位）、是有限數值，尺寸／強度／根數須大於 0，否則列為「未寫入」。
- 寫入 `review`：`{by, at, source（計算書檔名）, pairing（配對狀態）, status: "pending-recalc", changes: [{id, label, unit, old, new}], analysis}`。
- 設計工具開啟時通知使用者、以新輸入重算，`status` 改為 `recalculated`；計算書列「審查修正紀錄」並註明「審查建議不等於設計已通過」。`review` 不計入輸入雜湊。
- 「建議值已寫入案件」是資料操作；「設計已通過」只能由對應版本的計算書判定。

### 3.5 版本配對與過期規則

- **PDF ↔ 案件檔**：計算書表頭「輸入 SHA-256」＝案件快照（去掉 `saved`、`members`、`conf`、`review`）的 `JSON.stringify` 雜湊。StructAudit-AI `utils/pairing.py` 重算比對，另核對模組、構件名稱、內力來源群組：相符為「已核對」，不符為「不符」（**不寫出調整後案件檔**），無雜湊為「未驗證」（照寫但標示）。
- **哪些修改讓哪些結果過期**：

| 變更 | 最低限度的後續動作 | 目前的提示 |
|---|---|---|
| 幾何、支承、載重或分析勁度假設 | 回 Midas 重分析、重新匯入 | （Midas 端，工具無法得知） |
| 斷面尺寸或材料 | 重做設計；若影響分析勁度、自重或材料，回 Midas 重分析 | 計算書「內力來源」比對匯入時的 `secv`，不同即提示；審查寫回時 `review.analysis` 提示 |
| 配筋、箍筋間距 | 重做所有相關設計檢核；非線性或勁度依配筋時亦更新分析 | 設計工具開啟即重算 |
| 構件名稱、說明文字 | 只更新顯示與文件 | 不強迫重做 |

## 4. 各工具的工作項目

### RC 構件設計工具（本倉庫）
- `core/midas-io.js`：純函式（不碰 DOM），網頁與 Node 測試共用。
- 「從 Midas 匯入」對話框（柱、梁兩模組的載重卡片）：.mct（選填）＋內力表（貼上／.txt／.csv／.xlsx）→ 選群組 → 預覽 → 套用或批次建立構件。
- 案件檔 `loadsrc` 與計算書「內力來源」。
- M2（完成）：Plate Force → 單位寬版（Wood-Armer，$M_x^* = M_x + |M_{xy}|$ 等）。
- M3：配筋 MCT 輸出。

### midas-curve-gen
- 文件：建議「一個設計構件一個群組」的命名規則（M5）；不需改輸出格式。

### StructAudit-AI
- 計算書表頭擷取與 Agent 提示加入「內力來源」，審查者可核對極值篩選是否漏列（M4）；PDF／案件檔配對核對與寫回驗證（§3.4、§3.5）。

### 書稿
- 第六篇新增一章串接教學與例題（M6），x_verify 列入待實機核對項目。

### 7.1 使用者決定（2026-11-08）

1. **適用場景：建築、橋梁、水工全部支援**。設計工具三種設計依據並行；從 Midas 匯入不限設計依據（$P_D$ 只在橋梁容量設計使用），StructAudit-AI 依計算書的設計依據查對應規範。新增功能不得只做橋梁而破壞建築／水工模式（測試以預設建築模式與橋梁示範檔兩者涵蓋）。
2. **AI 審查預設維持現狀**（三輪），不改預設輪數；任務分流或縮減呼叫須先以固定測試集比較漏報、誤報、條文核對與費用再決定。
3. 多人共用：說明與選項見對話紀錄，待使用者確認團隊規模與 IT 限制後再定（預設仍為本機單人＋共用檔案格式）。
